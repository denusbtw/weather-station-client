# Weather Station Client

Android-застосунок для лабораторних робіт №1–3. Барометр з лабораторної №1 показує тиск і погодний стан. У лабораторній №2 додано програмну імітацію BLE-хаба; фізичний Bluetooth для демонстрації не потрібен. Лабораторна №3 додає синхронізацію тиску з Firebase Realtime Database.

## Віртуальний BLE-профіль

| Елемент | UUID | Операція |
| --- | --- | --- |
| Weather Station Hub service | `7f0b1000-65e8-4b26-a9f0-9d6417a90201` | GATT-сервіс |
| Status characteristic | `7f0b1001-65e8-4b26-a9f0-9d6417a90201` | Read, Notify |
| Data characteristic | `7f0b1002-65e8-4b26-a9f0-9d6417a90201` | Write |

Протокол передачі: застосунок записує рядок `PRESSURE_HPA=1013.2` у Data characteristic. Після підключення хаб повертає `READY` через Read; після запису відповідає `RECEIVED` через Notify. Це події `MockBleConnector`, а не реальні GATT-виклики. Усі події з'являються в терміналі застосунку та в Logcat із тегом `MockBleConnector`.

## Перевірка в емуляторі

1. Запустити застосунок та натиснути **Пошук пристроїв**. Приблизно за 2 секунди з'явиться `Weather Station Hub`.
2. Натиснути **Підключитися**. Статус зміниться на `Connected`, у терміналі з'явиться `READ ... READY`.
3. Змінити тиск повзунком або віртуальним сенсором і натиснути **Надіслати поточний тиск**. У терміналі та Logcat з'являться `WRITE` і `NOTIFY ... RECEIVED`.
4. Натиснути **Відключитися** або згорнути застосунок. Статус зміниться на `Disconnected`.

Дозволи Bluetooth для Android 12+ та старіших версій задекларовано в `AndroidManifest.xml` відповідно до завдання. Mock-реалізація не звертається до Bluetooth API, тому не запитує ці дозволи під час роботи. Для справжнього BLE-клієнта треба буде додати перевірку й запит дозволів під час виконання.

## Лабораторна №3: Firebase Realtime Database

Android-застосунок зареєстрований у Firebase з пакетом `com.example.weatherstationclient`. Файл конфігурації лежить у `app/google-services.json`; його URL бази читається через `FirebaseApp`. Для автоматичного надсилання використано **Firebase REST API + Retrofit 2 + Gson (OkHttp)**. Цей транспорт дозволяє одночасно зберігати реальні вимірювання у Firebase й переглядати ті самі запити в Android Studio Network Inspector.

База: `https://weather-station-2ad61-default-rtdb.europe-west1.firebasedatabase.app/`.

Поки екран застосунку активний, корутина кожні 5 секунд бере поточний тиск і передає його сервісу синхронізації на `Dispatchers.IO`. `FirebaseSensorSync` спочатку зберігає вимірювання в локальній черзі `SensorOutbox`, потім `FirebaseRestClient` виконує `PUT sensor_data/<deviceId>/<recordId>.json`. Кожне вимірювання має окремий UUID `recordId`:

```json
{
  "deviceId": "installation-uuid",
  "timestamp": 1792857600000,
  "value": 1013.25,
  "type": "pressure",
  "unit": "hPa"
}
```

`deviceId` генерується один раз і зберігається локально, `timestamp` — час вимірювання в мілісекундах Unix. На цьому екрані використовується барометр, тому payload має одне поле `value`, а не координати акселерометра `x/y/z`.

`PreferencesSensorStore` зберігає чергу як JSON у SharedPreferences синхронним `commit()` на фоновому потоці. Запис видаляється тільки після успішної HTTP-відповіді Firebase та успішного збереження нової черги. Після відновлення інтернету або перезапуску процесу відкладені записи надсилаються з початковими ID та timestamp. Повторний `PUT` за тим самим шляхом не створює дублікатів, навіть якщо сервер прийняв запис, а відповідь загубилася. Повторні спроби виконуються при зміні мережі та кожні 5 секунд; одночасно працює лише один завантажувач.

Нові вимірювання не створюються, коли застосунок згорнутий; уже прийнята черга може продовжувати надсилатися, доки процес живий. Сервіс належить Application, тому поворот екрана не створює другу чергу чи другий спостерігач з'єднання.

Картка «Хмарна синхронізація» показує Pending без інтернету або під час очікування повтору, надсилання, зелений статус лише після успішної відповіді Firebase і червоний статус при помилці. Відсутність інтернету також супроводжується Toast. Показано розмір черги, останній успішний HTTP-статус, час і значення запису. Логи мають тег `FirebaseSensorSync`.

### Доступ до бази

Locked mode початково забороняє запис. Для демонстрації у Firebase Console → Realtime Database → Rules можна опублікувати тимчасовий доступ лише до `sensor_data`:

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "sensor_data": {
      ".write": "now < 1793404800000"
    }
  }
}
```

Ці правила дозволяють публічний запис тестових даних до **31 жовтня 2026 року, 00:00 UTC**. Читання з Android закрите; для перегляду використовуй вкладку Data в консолі. Після цієї дати запис буде відхилено. Для подальшого використання потрібно налаштувати Firebase Authentication і правила доступу за користувачем.

### Перевірка синхронізації

1. Виконати Gradle Sync і запустити застосунок з інтернетом. Через 5 секунд картка має стати зеленою.
2. У Firebase Console → Realtime Database → Data розгорнути `sensor_data` → ідентифікатор пристрою. Нові записи мають з'являтися кожні 5 секунд.
3. Змінити тиск повзунком (на емуляторі з активним сенсором — змінити значення віртуального барометра). Перевірити наступний запис: нове `value`, новий `timestamp`, `type = pressure`.
4. Вимкнути інтернет на пристрої. Перевірити Toast і Pending. Змінити тиск і залишити застосунок відкритим щонайменше 5 секунд.
5. Відновити інтернет. Переконатися, що відкладені вимірювання з'явилися в базі й індикатор став зеленим.
6. Якщо показано `HTTP 401`/`Permission denied`, перевірити опубліковані Rules, шлях `sensor_data` й термін доступу. Якщо Pending триває з інтернетом — перевірити URL бази та Logcat.

### Скриншот Network Inspector

Мережеву передачу виконує Retrofit поверх OkHttp, який підтримує Network Inspector. Окремих діагностичних запитів чи кнопок немає: інспектор показує звичайні автоматичні записи тиску в Firebase.

1. Запустити оновлений debug-застосунок.
2. В Android Studio відкрити App Inspection → Network Inspector й вибрати процес `com.example.weatherstationclient`.
3. Зачекати 5–10 секунд, залишаючи застосунок активним. З'являтимуться звичайні `PUT`-запити до `firebasedatabase.app`.
4. Виділити проміжок передачі, вибрати запит і відкрити Request/Response для перегляду JSON. Зберегти скриншот із URL, HTTP 200 і тілом запиту.
5. У Firebase відкрити `sensor_data/<deviceId>/<recordId>` — ID і дані мають відповідати вибраному запиту.
